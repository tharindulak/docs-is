This guide walks you through configuring {edition.productName} to issue a verifiable credential (VC) to an OID4VCI-compatible digital wallet. Any wallet that supports the [OID4VCI specification](https://openid.net/specs/openid-4-verifiable-credential-issuance-1_0.html) can receive credentials from {edition.productName}.

## Prerequisites

Before you begin, ensure the following:

- An OID4VCI-compatible digital wallet is installed on your device.
- A user exists in {edition.productName} whose attributes you want to include in the credential.

## Step 1: Create a credential template

A **credential template** defines the name, format, and included attributes of a verifiable credential.

To create a credential template:

1. On the {edition.productName} Console, go to **Verifiable Credentials**.

2. Click **+ New Credential Template**.

    <Variants><Edition only="cloud"><img src={require("../../../assets/cloud/img/guides/verifiable-credentials/create-credential-template.png").default} alt="Create Credential Template dialog" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../assets/self-hosted/img/guides/verifiable-credentials/create-credential-template.png").default} alt="Create Credential Template dialog" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

3. Fill in the credential template details:

    | Field | Description | Example |
    | :---- | :---------- | :------ |
    | **Identifier** | A unique name that becomes the credential scope. Use lowercase with underscores. | `work_id` |
    | **Display Name** | A human-readable name shown in the wallet. | `Work ID` |
    | **User Attributes** | The user attributes include in the credential. | `given_name`, `family_name`, `email` |

4. Click **Create** to save the template.

    <Variants><Edition only="cloud"><img src={require("../../../assets/cloud/img/guides/verifiable-credentials/credential-template-detail.png").default} alt="Work ID credential template detail page" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../assets/self-hosted/img/guides/verifiable-credentials/credential-template-detail.png").default} alt="Work ID credential template detail page" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

## Step 2: Register a Digital wallet application

A **Digital wallet application** represents the digital wallet in {edition.productName}. It holds the OAuth 2.0 client configuration that the wallet uses to exchange authorization codes for access tokens.

To register a Digital wallet application:

1. On the {edition.productName} Console, go to **Applications** and click **+ New Application**.

2. Select **Digital Wallet Application** from the application type list.

    <Variants><Edition only="cloud"><img src={require("../../../assets/cloud/img/guides/verifiable-credentials/vc-client-app-type.png").default} alt="Application type selection highlighting Digital Wallet Application" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../assets/self-hosted/img/guides/verifiable-credentials/vc-client-app-type.png").default} alt="Application type selection highlighting Digital Wallet Application" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

3. Fill in the application details:

    | Field | Description |
    | :---- | :---------- |
    | **Name** | A descriptive name for the wallet application (e.g., `Lissi Wallet`). |
    | **Authorized Redirect URL** | The wallet's OID4VCI callback URL. See your wallet's documentation for this value. |

4. Click **Create**.

    <Variants><Edition only="cloud"><img src={require("../../../assets/cloud/img/guides/verifiable-credentials/vc-client-app-create.png").default} alt="Digital Wallet Application creation dialog" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../assets/self-hosted/img/guides/verifiable-credentials/vc-client-app-create.png").default} alt="Digital Wallet Application creation dialog" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

## Step 3: Allow the wallet to request the credential

Once the Digital Wallet application is created, you must allow it to request the credential.

1. In the newly created application, go to **Authorize** tab and  click **Authorize Verifiable Credential**.

    <Variants><Edition only="cloud"><img src={require("../../../assets/cloud/img/guides/verifiable-credentials/authorize-vc-dialog.png").default} alt="Authorize Verifiable Credential dialog" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../assets/self-hosted/img/guides/verifiable-credentials/authorize-vc-dialog.png").default} alt="Authorize Verifiable Credential dialog" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

2. Fill in the authorization details:

    | Field | Description | Example |
    | :---- | :---------- | :------ |
    | **Verifiable Credential** | The credential template to authorize for this application. | `work_id` |
    | **Authorization Policy** | The access policy to enforce. Select **No Authorization Policy** or **Role Based Access Control (RBAC)** to apply authorization policy. | `No Authorization Policy` |

3. Click **Finish**.

The application is now allowed to request the `work_id` credential scope on behalf of an authenticated user.

## Step 4: Retrieve the credential offer URI

The **credential offer URI** is a link the wallet follows to begin the issuance flow.

To retrieve the offer URI:

1. On the {edition.productName} Console, go to **Verifiable Credentials** and select your credential template (e.g., **Work ID**).

2. Locate the **Credential Offer** section and copy the URI. It appears in the format:

    ```text
    openid-credential-offer://?credential_offer_uri=https://localhost:9443/oauth2/credential-offer/<offer-id>
    ```

:::note
The {edition.productName} Console does not generate a QR code. To share the offer with a mobile wallet, paste the URI into an external QR code generator and present the resulting QR code for the wallet to scan.
:::

## Configure VC attribute mappings

{edition.productName} maps user profile attributes to verifiable credential claims using the **Verifiable Credentials** attribute dialect. Default mappings are pre-loaded for common claims such as `given_name`, `family_name`, and `email`.

To view or update the attribute mappings:

1. On the {edition.productName} Console, go to **User Attributes & Stores** > **Attributes**.

2. Under **Manage Attribute Dialects**, click **View** on the **Verifiable Credentials** dialect.

    <Variants><Edition only="cloud"><img src={require("../../../assets/cloud/img/guides/verifiable-credentials/vc-attribute-dialect.png").default} alt="VC attribute dialect page" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../assets/self-hosted/img/guides/verifiable-credentials/vc-attribute-dialect.png").default} alt="VC attribute dialect page" width="700" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

3. Review the available claim mappings. Each mapped claim corresponds to a local claim URI (e.g., `http://wso2.org/claims/givenname`) that is resolved from the user's profile at issuance time.

:::note
You can add custom claim mappings if you need to include additional user attributes in your credentials.
:::
