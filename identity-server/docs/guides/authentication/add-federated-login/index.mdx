## Configure JIT provisioning

<Variants>

<Edition only="cloud">

When a user logs in with an external identity provider using the same email address registered in a local account, JIT-provisioning overrides the attributes of the local account with the attributes received from the external identity provider.

{edition.productName}, by default, enables Just-In-Time (JIT) user provisioning for your external identity provider.

To disable JIT-provisioning,

1. On the {edition.productName} Console, click **Connections** and select the relevant connection.

2. Go to the **Just-in-Time Provisioning** tab of the selected connection.

3. Check/Uncheck the **Just-in-Time (JIT) User Provisioning** checkbox to enable/disable it.

    <img src={require("../../../../assets/cloud/img/guides/jit-provisioning/jit-enabled.png").default} alt="enable/disable JIT user provisioning" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

4. Click **Update** to save the changes.

:::note
- Learn more about JIT provisioning configurations in [configure JIT user provisioning](../jit-user-provisioning.mdx).

- You can use the [identity provider APIs](../../../reference/apis/idp/index.mdx#op-getJITConfig) to customize the attribute syncing behavior between the external identity provider and {edition.productName}.
:::

</Edition>

## Map groups with {edition.productName}

### Map local attributes to external attributes

Follow the steps below to map attributes of {edition.productName} with that of a connection.

1. On the {edition.productName} Console, go to **Connections**.

2. Select your connection and go to its **Attributes** tab.

3. Click **Add Attribute Mapping** to add a new attribute mapping.

    <img src={require("../../../../assets/img/guides/idp/group-mapping/add-attribute-mappings.png").default} alt="Add attribute mappings" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

4. Enter the  **External IdP Attribute** of the connection and map it to the **Groups** attribute of {edition.productName}.

    <img src={require("../../../../assets/img/guides/idp/group-mapping/add-new-group-attribute-mapping.png").default} alt="Add new group attribute mapping" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

5. Click **Add Attribute Mapping** and then click **Save**.

    <img src={require("../../../../assets/img/guides/idp/group-mapping/stage-new-group-attribute-mapping.png").default} alt="Stage new group attribute mapping" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

6. Click **Update** to save the changes.

    <img src={require("../../../../assets/img/guides/idp/group-mapping/submit-attribute-mappings.png").default} alt="Submit attribute mappings" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

<Edition only="self-hosted">

### Add required attributes for provisioning

When provisioning users from an external identity provider (IdP), you may want to include specific attributes in the user’s profile. Follow the steps below to define the required attributes and assign default values.

1. On the {edition.productName} Console, go to **Connections**.
2. Select your connection and go to its **Attributes** tab.
3. Under **Provisioning Attributes Selection**, click **Add Attribute**.
4. Move the attributes that you want to include in the provisioned user's profile and click **Save**.

    <img src={require("../../../../assets/self-hosted/img/guides/idp/add-required-attributes-for-provisioning.png").default} alt="Add required attributes for provisioning" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

5. Add a default value to the attribute. If the federated user lacks data for it, the system adds the default to the provisioned user’s profile.

    <img src={require("../../../../assets/self-hosted/img/guides/idp/add-default-value-for-required-attributes.png").default} alt="Add default value for required attributes" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

    :::note
    To add default values to the provisioned user’s profile when the federated user has no value, configure the following in the `<IS_HOME>/repository/conf/deployment.toml` file.

    ```toml
    [authentication.endpoint]
    enable_merging_custom_claim_mappings_with_default = true
    ```
    :::

</Edition>

## Configure home realm identifier

The home realm identifier is a unique value that identifies a connection when routing users directly to a specific external IdP during login. When a user initiates login, your application can include this identifier as the `fidp` query parameter in the authorization request, which causes {edition.productName} to skip the login page and route the user directly to the specified external IdP.

To configure the home realm identifier:

1. On the {edition.productName} Console, click **Connections** and select the relevant connection.

2. Go to the **Advanced** tab of the selected connection.

3. Enter a unique identifier in the **Home Realm Identifier** field.

    <Variants><Edition only="cloud"><img src={require("../../../../assets/cloud/img/guides/connections/home-realm-identifier.png").default} alt="Home realm identifier configuration" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition><Edition only="self-hosted"><img src={require("../../../../assets/self-hosted/img/guides/connections/home-realm-identifier.png").default} alt="Home realm identifier configuration" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} /></Edition></Variants>

4. Click **Update** to save the changes.

Once configured, use this identifier in your application's authorization request as follows:

```bash
https://<host_name>/t/<org_name>/oauth2/authorize?
  response_type=code
  &client_id=<client_id>
  &redirect_uri=<redirect_uri>
  &scope=openid
  &fidp=<home_realm_identifier>
```

:::note
When the `fidp` parameter is provided, {edition.productName} bypasses the login page and directly initiates the authentication flow with the matching external IdP.
:::

## Delete a connection

{/* markdownlint-disable-next-line */}

:::note[Before you begin]
If your connection has applications associated with it, you will not be able to delete the connection.

Before deleting such connections:

1. Check the associated applications from the **Connected Apps** tab of the connection.
2. Click on an application that uses the connection and you will be redirected to the Login Flow tab of the respective application.
3. Remove the connection from the sign-in flow of the associated applications.
4. Repeat steps 2 and 3 for all listed applications.
5. Proceed to delete the connection.
:::

To delete a connection:

1. On the {edition.productName} Console, go to **Connections**.
2. Click **Set up** and navigate to the **General** tab.
3. At the bottom of the page, click the button in the **Delete connection**.

    :::note
    You cannot delete connections that are available by default.
    :::

3. Select the checkbox and confirm your action.

    <img src={require("../../../../assets/img/guides/idp/delete-idp/confirmation-modal.png").default} alt="Delete connection" width="500" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />
