You can connect an AWS Cognito user pool to your applications using {edition.productName} and let users log in with their existing AWS Cognito accounts.

AWS Cognito user pools act as an OpenID Connect (OIDC) identity provider. {edition.productName} connects to AWS Cognito as a standard OIDC identity provider using the authorization code flow.

Follow this guide to register {edition.productName} in AWS Cognito and add AWS Cognito to the login flow of your application.

:::note
For detailed instructions on configuring AWS Cognito, refer to the [AWS Cognito documentation](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools.html).
:::

## Register {edition.productName} in AWS Cognito

You need to register {edition.productName} as an app client in an AWS Cognito user pool.

### Create a user pool and an app client

If you already have a user pool, skip to step 4 and create a new app client in the existing user pool.

1. Sign in to the [AWS Management Console](https://console.aws.amazon.com/) and open the [AWS Cognito console](https://console.aws.amazon.com/cognito/home).

2. Go to **User pools** and click **Create user pool**.

    <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/user-pool-initial-creation.png").default} alt="Create User pools" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

3. Under **Define your application**, select **Traditional web application** as the application type and enter a name for the application.

    <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/user-pool-creation.png").default} alt="Create traditional application" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

4. Under **Configure options**, select the sign-in identifiers and the required sign-up attributes for your users. For example, select **Email** as the sign-in identifier.

5. Under **Add a return URL**, enter the following URL. AWS Cognito redirects users to this URL after they log in.

    ```bash
    {edition.productUrlFormat}/commonauth
    ```

6. Click **Create user directory** to create the user pool and the app client.

### Get the app client credentials

1. On the AWS Cognito console, select your user pool.

2. Go to **Applications** > **App clients** and select the app client you created.

    <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/view-apps.png").default} alt="View app" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

3. Under **App client information**, copy **Client ID** and the **Client secret**.

:::tip[Verify the login pages of the app client]
AWS Cognito accepts a login request only if the request matches the login pages configuration of the app client. If the callback URL, grant type, or scopes that {edition.productName} sends aren't allowed, AWS Cognito rejects the request with an error such as `redirect_mismatch` or `invalid_scope`, and the user can't log in.

When you create a **Traditional web application**, AWS Cognito configures the login pages for you. If you use an existing app client, or if login fails with one of these errors, verify the configuration as follows:

1. On the app client, go to the **Login pages** tab and click **Edit** under **Managed login pages configuration**.

2. Make sure the following values are set and click **Save changes**.

    - **Allowed callback URLs**: `{edition.productUrlFormat}/commonauth`
    - **Identity providers**: **Cognito user pool directory**
    - **OAuth 2.0 grant types**: **Authorization code grant**
    - **OpenID Connect scopes**: **OpenID**, **Email**, and **Profile**
:::

### Get the user pool endpoints

{edition.productName} needs the OpenID Connect endpoints of your user pool. These endpoints are built from the domain, the region, and the ID of the user pool.

#### Get your domain

1. On the AWS Cognito console, select your user pool.

2. Go to **Branding** > **Domain** and take note of the **Domain**. If the user pool doesn't have a domain yet, click **Actions** > **Create Cognito domain** and create one.

    The domain takes one of the following formats:

    - Cognito domain: `https://<domain_prefix>.auth.<region>.amazoncognito.com`
    - Custom domain: `https://<your_custom_domain>`

    <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/view-domain.png").default} alt="View domain" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

#### Endpoints

1. On the AWS Cognito console, go to **Overview** of your user pool and take note of the **User pool ID** and the AWS region of the user pool.

2. Use the domain, the region, and the user pool ID to build the endpoints that {edition.productName} needs:

    | Endpoint | URL |
    | --- | --- |
    | Authorization endpoint | `https://<cognito_domain>/oauth2/authorize` |
    | Token endpoint | `https://<cognito_domain>/oauth2/token` |
    | User info endpoint | `https://<cognito_domain>/oauth2/userInfo` |
    | JWKS endpoint | `https://cognito-idp.<region>.amazonaws.com/<user_pool_id>/.well-known/jwks.json` |

    :::tip
    You can verify these values in the OpenID Connect discovery document of the user pool at `https://cognito-idp.<region>.amazonaws.com/<user_pool_id>/.well-known/openid-configuration`.
    :::

### Create a user in the user pool

To try out the login flow, you need a user account in the AWS Cognito user pool. If the user pool doesn't have a user yet, follow the steps below to create one.

1. On the AWS Cognito console, select your user pool.

2. Go to **User management** > **Users** and click **Create user**.

3. Enter the following details of the user:

    | Parameter | Description |
    | --- | --- |
    | Invitation message | Select **Don't send an invitation** to share the credentials with the user yourself, or **Send an email invitation** to email the temporary password to the user. |
    | Email address | The email address of the user. Select **Mark email address as verified** so that the user can log in without verifying the email address. |
    | Temporary password | Select **Set a password** and enter a password, or select **Generate a password** to let AWS Cognito generate one. |

    :::note
    The fields you see depend on the sign-in identifiers and required attributes you selected when creating the user pool. For example, if you selected **Username** as a sign-in identifier, you need to enter a **User name** as well.
    :::

4. Click **Create user**.

     <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/create-user.png").default} alt="Create user in Cognito" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

AWS Cognito creates the user with the **Force change password** status. The user must change the temporary password at the first login.

:::tip
Instead of creating users manually, you can let users create their own accounts. To do so, go to **Authentication** > **Sign-up** on your user pool and enable **Self-registration**. Users can then sign up from the AWS Cognito managed login page.
:::

## Register the AWS Cognito IdP

Now, let's register AWS Cognito as a connection in {edition.productName}.

1. On the {edition.productName} Console, go to **Connections**.

2. Click **Create Connection** and select **Standard-Based IdP**.

3. Enter a unique name for the identity provider, for example, `AWS Cognito`, select **OpenID Connect**, and click **Next**.

    <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/create-connection.png").default} alt="Create OIDC IdP in WSO2 Identity Platform" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

4. Enter the following details of AWS Cognito and click **Next**:

    | Parameter | Description |
    | --- | --- |
    | Client ID | The client ID of the AWS Cognito app client. |
    | Client secret | The client secret of the AWS Cognito app client. |
    | Authorization endpoint URL | `https://<cognito_domain>/oauth2/authorize` |
    | Token endpoint URL | `https://<cognito_domain>/oauth2/token` |

    <img src={require("../../../../../assets/cloud/img/guides/idp/aws-cognito/create-connection-wizard2.png").default} alt="Add endpoints in WSO2 Identity Platform" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

5. Select **JWKS endpoint** as the mode of certificate configuration and enter the JWKS endpoint of the user pool.

    ```bash
    https://cognito-idp.<region>.amazonaws.com/<user_pool_id>/.well-known/jwks.json
    ```

    {edition.productName} uses this endpoint to validate the signature of the ID tokens that AWS Cognito issues.

6. Click **Finish** to complete the registration.

### Configure the scopes

By default, {edition.productName} requests only the `openid` scope from the external identity provider. To receive the user's email and profile attributes from AWS Cognito, add the required scopes.

1. On the created connection, go to the **Settings** tab.

2. Under **Scopes**, add `email` and `profile`.

    :::note
    The scopes you add here must be enabled under **OpenID Connect scopes** of the AWS Cognito app client.
    :::

3. Optionally, enter `https://cognito-idp.<region>.amazonaws.com/<user_pool_id>/oauth2/userInfo` as the **Userinfo Endpoint URL**.

4. Click **Update** to save your changes.

## Configure user attributes

AWS Cognito returns user attributes as standard OpenID Connect claims such as `sub`, `email`, `email_verified`, `given_name`, and `family_name`. The `sub` claim holds a unique identifier that AWS Cognito generates for the user.

Configuring attributes for an Identity Provider (IdP) involves mapping the attributes available in the external IdP to local attributes. This is done so that {edition.productName} can identify the user attributes in the response sent from the external IdP.

To do so,

1. On the {edition.productName} Console, click **Connections**.

2. Select the relevant IdP connection from the list and click **Set up**.

3. Go to the **Attributes** tab and under **Identity Provider Attribute Mappings**,  click **Add Attribute Mapping**.

    <img src={require("../../../../../assets/img/guides/idp/saml-enterprise-idp/go-to-user-attribute-page.png").default} alt="Go to attributes section in IdP" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

4. Enter the external attribute, select the corresponding local attribute to which it maps and click **Add Attribute Mapping**.

    <img src={require("../../../../../assets/img/guides/idp/saml-enterprise-idp/map-saml-idp-attributes.png").default} alt="Map IdP attributes" width="600" style={{display: "block", margin: "0", border: "0.3px solid lightgrey"}} />

5. Click **Save** to save the entries.

6. Under **Subject**, select a **Subject Attribute** that will be used to uniquely identify the user.

7. Under **Provisioning Attributes Selection**, select the required attributes that needs to be sent in the response to provision the user in {edition.productName}.

8. Click **Update** to save the changes.
