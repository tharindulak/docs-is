OpenID Connect provides [OpenID Connect RP-Initiated Logout](https://openid.net/specs/openid-connect-rpinitiated-1_0.html) to terminate user sessions. The logout endpoint is used to terminate the user session at {edition.productName} and to log the user out. When a user is
successfully logged out, the user is redirected to the `post_logout_redirect_uri` sent in the logout request.

<Variants>

<Edition only="cloud">

:::note
Your application should redirect the user's browser to the logout endpoint, as {edition.productName} uses the browser session to identify the session to terminate. To terminate user sessions from a backend service, use the [Session Management API](../../../../reference/apis/session/index.mdx). The application calling this API should be [authorized](../../../applications/register-machine-to-machine-app.mdx#authorize-the-api-resources-for-the-app) to access the **Session Management API** with the `internal_session_delete` scope.
:::

</Edition>

<Edition only="self-hosted">

:::note
Your application should redirect the user's browser to the logout endpoint, as {edition.productName} uses the browser session to identify the session to terminate. To terminate user sessions from a backend service, use the [Session Management API](../../../../reference/apis/session-mgt-rest-api/index.mdx). The application calling this API should be [authorized](../../../applications/register-machine-to-machine-app.mdx#authorize-the-api-resources-for-the-app) to access the **Session Management API** with the `internal_session_delete` scope.

</Edition>

## Logout endpoint

```text
{edition.productUrlFormat}/oidc/logout
```

## Sample request

Redirect the user's browser to the logout endpoint with the following parameters. Make sure to URL-encode the parameter values.

```text
{edition.productUrlSample}/oidc/logout?
id_token_hint=<id_token>
&post_logout_redirect_uri=<post_logout_redirect_uri>
&state=<state>
```

The logout request has the following parameters:

:::note
See [RP-initiated logout request](https://openid.net/specs/openid-connect-rpinitiated-1_0.html#RPLogout) for more details.
:::

<table>
  <tbody>
    <tr>
      <th>Request Parameter</th>
      <th>Description</th>
    </tr>
    <tr>
      <td>

        `id_token_hint`

      </td>
      <td>The ID token that {edition.productName} returned to the application in the token response. It gives {edition.productName} a hint about the user's current authenticated session on the application.</td>
    </tr>
    <tr>
      <td>

        `client_id`

      </td>
      <td>The client ID obtained when registering the application in {edition.productName}. This can be used instead of the `id_token_hint` parameter.</td>
    </tr>
    <tr>
      <td>

        `post_logout_redirect_uri`

      </td>
      <td>The URL to redirect the user to after logout. The value defined here should be added as one of the [authorized redirect URLs](../../../../reference/app-settings/oidc-settings-for-app.mdx#authorized-redirect-urls). This should be passed along with either the `id_token_hint` or the `client_id`. If the `post_logout_redirect_uri` parameter is not passed, the user will be routed to {edition.productName}'s common page after logout.</td>
    </tr>
    <tr>
      <td>

        `state`

      </td>
      <td>The parameter passed from the application to {edition.productName} to maintain state information. If an application sends this parameter, {edition.productName} will return this information in the response.</td>
    </tr>
  </tbody>
</table>

## Sample response

```text
http://myapp.com?state=state-param
```

If **Skip logout consent** is disabled for the application, {edition.productName} prompts the user to confirm the logout before logging the user out. To configure this, go to **Applications** in the {edition.productName} Console, select your application, and use the **Skip logout consent** option in its **Advanced** tab.
